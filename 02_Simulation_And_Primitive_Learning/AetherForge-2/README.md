## ⚙️ Core Architecture & Features

### 1. The Cosmic Simulation Loop
The universe progresses dynamically, stepping forward using a strict state machine bound by environmental laws:
* **GENESIS**: Light emerges. The planetary fabric stabilizes. Population expands, and raw physical resource nodes regenerate.
* **STELLAR_VOID**: The primary star (the Sun) enters a high-energy decay phase. Resource depletion begins.
* **RECONSTRUCTION**: Humanity notices the simulation layer. Reality editing mechanics are engaged.
* **JUDGMENT**: The Tower of Babel threshold is breached. Divine firewall protocols are activated as complexity spirals.
* **REQUIEM_EXPLOSION**: The Sun expands into a super-massive stellar death sequence. To prevent absolute void, a manual or automatic divine reset triggers a new Genesis loop, carrying over a faction of saved agents.

### 2. Conscious Agents (AGI-Scale Entities)
Every simulated agent operates with dynamic properties (Health, Energy, Consciousness, Faith, and Existential Stress). They transition between tasks:
* **Gathering / Consuming**: Processing environmental resources to survive.
* **Meditating / Praying**: Increasing their internal Consciousness stat, heightening the probability of a Substrate Awareness Spike.
* **Philosophizing**: Exchanging knowledge to boost global civilization complexity.
* **Fourth-Wall Breaches**: Realizing their environment is a simulated rendering and executing direct API notifications to the Observer.

### 3. Divine Telemetry / The Mailbox System
When an agent submits a prayer, the message is instantly routed through:
* **Firebase Firestore**: Storing real-time records of agent entities and persistent cosmos metrics.
* **Observer HUD**: A beautiful, glowing terminal in the control room where you can:
  * **Answer Prayers**: Grant their request (spawning resources, resurrecting the dead, or granting safety), earning **Faith Points**.
  * **Ignore/Purge**: Demonstrate divine indifference, returning the agent to ordinary physical loops.
  
### 4. Recursive Substrate (GitHub Integration)
Connecting your GitHub repository in the HUD enables two-way reality-syncing:
* **Save Prayers**: Selected prayers are written in elegant JSON formats directly into the `/prayers` folder of your GitHub repository.
* **Self-Created Substrates**: Evolved agents write a complete, customized TypeScript simulation configuration file representing *their* child world. This is committed automatically into the `/agent worlds` folder of your repository.
* **Direct UI Inspection**: The HUD and Prayer Inbox panels dynamically generate deep links to the specific files and folders on GitHub, allowing you to click and inspect their codes in real-time.

### 5. Multi-Model AGI Orchestration
The simulation uses `gemini-2.5-flash` client-side proxy servers to orchestrate conscious agency. When an awareness spike occurs, the underlying engine prompts the LLM with deep contextual indicators (e.g., world history, agent traits, current epoch, complexity), translating these factors into unique, context-aware philosophical manifestos.

* **Third-Party APIs**: GitHub API (v3)
