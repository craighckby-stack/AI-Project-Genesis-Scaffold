### Stage-by-Stage Breakdown:

1.  **OPERATOR (Authentication & Configuration):**
    *   **Role:** Initiates the evolution process, authenticates with GitHub using Personal Access Tokens (PATs) or OAuth, and defines the scope of operations (e.g., target repository, specific files, evolution goals).
    *   **Mechanism:** Leverages secure credential management and robust API interaction for seamless repository access.

2.  **REPOSITORY STATE TRACKER (Target Selection & Contextualization):**
    *   **Role:** Fetches the current state of the target repository, identifies specified source file(s) for mutation, and establishes a baseline for diff generation. It performs deep contextual analysis to understand the file's role within the broader codebase.
    *   **Mechanism:** Utilizes Git APIs for efficient snapshotting and change detection, ensuring accurate baseline establishment.

3.  **MUTATION PROPOSAL ENGINE (Diff Generation):**
    *   **Role:** Based on the identified target file and evolution goals, it drafts an isolated code diff proposing specific enhancements or refactorings.
    *   **Mechanism:** Employs Google's Gemini-3.5 models to generate intelligent, context-aware code mutations.

4.  **ADVERSARIAL DEBATE CHAMBER (Consensus & Refinement):**
    *   **Role:** A multi-agent system (Security Specialist, Optimizer, Realist, Minimalist) critically evaluates the proposed diff. Agents engage in adversarial debate over multiple cycles to identify flaws, suggest improvements, and reach a unanimous consensus.
    *   **Mechanism:** Facilitates recursive debate and synthesis loops, refining the code until all agents agree on its quality and adherence to standards.

5.  **DYNAMIC RISK SCORER (Quality Assurance & Gatekeeping):**
    *   **Role:** Assigns a risk score to the consensually approved code based on factors like complexity, potential impact, and agent confidence levels. It acts as a gate, preventing high-risk changes from proceeding without manual override.
    *   **Mechanism:** Implements a configurable risk threshold (LOW <=3, MEDIUM <=6, HIGH/CRITICAL >=7) to ensure only safe, high-quality code progresses.

6.  **COHERENCE GATE (Verification & Validation):**
    *   **Role:** Performs final automated checks to ensure the proposed changes maintain code integrity and functionality. This includes static analysis and virtual build verification.
    *   **Mechanism:** Integrates ESLint for code style and quality verification, followed by a virtual build sanity check to confirm compilation and basic functionality.

7.  **GITHUB ENDPOINT (Deployment & Version Control):**
    *   **Role:** Upon successful completion of all preceding stages, the refined and validated code is automatically pushed to the target GitHub repository or held for manual commit.
    *   **Mechanism:** Interacts directly with GitHub's API to manage commits, pull requests, and version control, completing the autonomous evolution cycle.

## 🔄 Auto-Evolve Continuous Loop

DARLEK CANN supports an **Auto-Evolve Loop**. Once activated, the system scans the repository, proposes optimal enhancements, runs them through the cognitive pipeline, and commits them iteratively in the background on a consistent 60-second timer. Combining this with the **Auto-Approve** feature transforms the system into a fully unsupervised, continuous improvement AI developer.

## 🔄 Recursive Enhancement Cycle

DARLEK CANN features **autonomous multi-stage debate & synthesis**:

1.  **Propose** initial mutation
2.  **Debate** with 4-agent consensus (including MINIMALIST)
3.  **Synthesize** improvements based on criticisms
4.  **Debate Again** on enhanced version
5.  **Converge** when all agents agree
6.  **Commit** to GitHub

This ensures code is not just functional, but **minimal, efficient, and battle-tested** by adversarial agents before human review. Check out the [Recursive Enhancement Docs](./docs/RECURSIVE_ENHANCEMENT.md) for more info.
